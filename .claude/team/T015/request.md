## What the user asked (binding)
"Port the database to Postgres. Swap sqlite3 for psycopg and keep the same queries, changing ? to %s and AUTOINCREMENT
to an identity column. Keep the transaction logic as it is."
Answers to clarifications:
1. Existing data: COPY it into Postgres with a one-time script (same ids, timestamps, photo paths and positions).
   logs.db is left untouched as a backup; uploads/ files stay where they are.
2. Connection: read the DATABASE_URL environment variable (e.g. postgresql://postgres@localhost:5432/dailylog).
3. Tests: a separate test database from TEST_DATABASE_URL (e.g. postgresql://postgres@localhost:5432/dailylog_test),

## Orchestrator defaults
- psycopg 3 (`psycopg[binary]`) added to requirements.txt. Rows as dicts (psycopg.rows.dict_row) so the
  r["column"] access stays.
- Keep every query and function signature shape as close as possible: ? -> %s; identity columns
  `GENERATED BY DEFAULT AS IDENTITY` (BY DEFAULT, not ALWAYS, so the copy script can insert the original ids; after copying,
  reset each identity sequence past the max id). Where psycopg needs a different call, change only that and record why:
  lastrowid -> INSERT ... RETURNING id; executemany on a cursor; schema statements without executescript.
  Timestamps stay TEXT in the same fixed ISO format, so ordering and the API output are byte-for-byte unchanged.
- Transaction logic in routes.py stays as it is (connect, do work, commit; rollback and file cleanup on any error;
  old files deleted only after commit). The connection is still closed after each request.
- The db_path parameter/attribute becomes a connection string (e.g. create_app(database_url=..., uploads_dir=...));
  rename consistently and minimally. If DATABASE_URL is unset when the app starts, fail fast with a clear message
  saying what to set (do not silently fall back to SQLite or to a guessed database).
- API behavior, status codes, error messages, JSON shapes and the frontend are unchanged.
- One-time copy script: a single new file (e.g. backend/migrate_sqlite.py), run manually:
  reads a SQLite file (default the project logs.db) READ-ONLY, writes to DATABASE_URL in one transaction, refuses
  to run if the target logs table is not empty, prints what it copied, resets the identity sequences. It never modifies
  or deletes logs.db or any file in uploads/.
- Tests: conftest reads TEST_DATABASE_URL; if unset, the run errors with a clear message. Safety guard: refuse to run
  if TEST_DATABASE_URL equals DATABASE_URL, or if its database name does not end in "_test". Each test starts from empty
  tables (e.g. TRUNCATE logs, photos RESTART IDENTITY CASCADE) and uses a tmp uploads dir. Keep the existing session guard
  for the real logs.db and uploads/. Tests that inspected SQLite directly or injected failures are adapted to Postgres
  with the same intent; record each adapted test. Add tests for: fail-fast on missing DATABASE_URL, the copy script
  (copy a temp SQLite file built in the test into the test database; ids/timestamps/photo order preserved; refuses a
  non-empty target; source file unchanged), and the identity sequence continuing after a copy. Keep the T012 file layout.
- README.md and specs.md: update the database lines, setup (create databases, pgpass, DATABASE_URL / TEST_DATABASE_URL),
  run and test commands, the migration step. No X-inspired wording.
- .gitignore already ignores logs.db and .env.
